# Polynomial Commitment Comparator

Демонстрационный web-инструмент для сравнения KZG, IPA и FRI в контексте zero-knowledge протоколов и рекурсивных доказательств.

## Что исправлено

В первой версии IPA слишком часто выигрывал из-за перекоса в скоринговой модели: ему одновременно давались высокие оценки за отсутствие toxic waste, рекурсию и приемлемую внешнюю проверку.

В этой версии логика разделена по сценариям:

- **KZG** должен выигрывать, когда главный критерий — минимальный proof size или короткая внешняя проверка при допустимом trusted setup.
- **IPA** должен выигрывать, когда важна рекурсивная проверка или pairing-free verifier.
- **FRI** должен выигрывать, когда требуется прозрачность, STARK-like архитектура или отсутствие SRS.

## Назначение

Инструмент не реализует криптографические протоколы KZG, IPA или FRI. Он показывает сравнительную модель по параметрам:

- размер полинома или вектора `n`;
- число полиномов `m`;
- число точек открытия `t`;
- число запросов FRI `q`;
- blowup factor для FRI;
- допустимость trusted setup;
- требование рекурсивной проверки;
- требование прозрачности;
- выбранный приоритет сравнения.

## Как запустить локально

Откройте файл `index.html` в браузере.

Можно также запустить локальный сервер:

```bash
python -m http.server 8000
```

После этого открыть:

```text
http://localhost:8000
```

## Как обновить GitHub Pages

1. Заменить старые файлы в репозитории на файлы из этой версии.
2. Убедиться, что `index.html` находится в корне репозитория.
3. Перейти в `Settings → Pages`.
4. Проверить, что выбрана ветка `main` и папка `/root`.
5. Подождать обновления GitHub Pages.

## Ограничения модели

Расчетные значения являются условными. Они не являются benchmark-результатами и не должны интерпретироваться как реальные размеры доказательств или время работы.

Модель не учитывает:

- конкретную elliptic curve;
- стоимость pairing в выбранной библиотеке;
- оптимизацию MSM;
- выбор поля;
- FFT/LDE-реализацию;
- конкретную хэш-функцию;
- параметры Fiat–Shamir transcript;
- особенности полной доказательной системы.

Цель инструмента — визуализировать компромиссы: KZG дает compact openings, IPA удобнее для pairing-free рекурсии, FRI дает прозрачность и STARK-like архитектуру.
